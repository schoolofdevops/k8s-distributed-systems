Distributed Systems with Docker & Kubernetes

From Containers to Cloud Native Orchestration — an 8-session hands-on workshop — by Gourav Shah, School of DevOps & AI.

An 8-session, 16-hour corporate workshop that takes one 3-tier sample application on a journey: first connected and deployed with Docker on a single host, then orchestrated, scaled, exposed and hardened on Kubernetes. Learners come away able to reason about distributed-systems concerns (state, scale, failure), operate the core Kubernetes workload and networking primitives, expose services safely with Ingress, manage configuration and access control, and map what they built back onto microservices architecture patterns.

Who this is for​

Corporate cohort of QAs and developers moving a non-microservices application to a microservices architecture, and platform engineers who will operate services on Kubernetes.

How to use this course​

Each module is a Lesson (concepts + analogies + diagrams), a Lab (copy-runnable, validated live), and a Quiz. Work them in order; the project spine — Fernwood Goods, a 3-tier sample app (Node frontend → Python backend → Postgres DB) that degrades gracefully at every tier — frontend shows its container identity and renders useful UI even when the backend is unreachable; backend serves both API and a status UI and reports DB availability instead of erroring — grows across modules into the capstone. Sessions 1–2 connect and deploy it with Docker networking and Compose on a single host. Sessions 3–8 grow the SAME app's Kubernetes manifests in place: Pods → Namespace + ReplicaSet + Services → Deployments → StatefulSet (Postgres) + PVCs → Envoy Ingress → ConfigMaps/Secrets/RBAC/NetworkPolicy, closing with the microservices-pattern mapping in Session 8.
